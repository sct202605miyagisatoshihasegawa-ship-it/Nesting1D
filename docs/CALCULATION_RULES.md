# Nesting1D V1.0.1 計算ルール

- 対象アプリバージョン：1.0.1
- 更新日：2026-08-10

## 1. 文書の目的

この文書は、Nesting1D V1.0.1で現在有効な計算・切断ルールを説明する技術資料である。開発途中の旧仕様や検討履歴は扱わない。

現行仕様全体は [REQUIREMENTS.md](REQUIREMENTS.md)、設計判断と採用理由は [DECISIONS.md](DECISIONS.md) を参照する。本書と実装の対応は、主に `app/calculation/engine.py`、`rules.py`、`patterns.py`、`selection.py`、`models.py` で確認できる。

---

## 2. 対象範囲

- 長さだけで表す一次元材料を対象とする。
- 母材から、入力された寸法と本数の必要部材を切り出す。
- 単位はmmとし、計算値は整数として扱う。
- 完全な数学的最適解や全配置の探索は保証しない。
- 限定した複数の貪欲的候補を比較し、現場で実行しやすい切断計画の作成を支援する。
- 同時に使用できる同一の材質、規格、加工条件の材料を1回の計算単位とする。

入力可能な行数・本数・寸法などの範囲は、`REQUIREMENTS.md`の「入力制約」を参照する。

---

## 3. 基本切断ルール

### 3.1 切断方向

- 材料の左端から右方向へ順に切断する。
- 右端側からの切断は行わない。
- 右端捨て切りは行わない。

### 3.2 左端捨て切り

購入新品材、在庫新品材、在庫残材のいずれも、材料1本の使用開始時に左端捨て切りを行う。在庫残材を再利用する場合も同じ規則を適用する。

左端処理による消費長は次のとおりである。

```text
左端処理の消費長 = 左端捨て切り寸法 + 鋸刃厚1回分
```

左端捨て切り寸法が0mmでも左端処理は省略せず、鋸刃厚1回分を消費する。鋸刃厚自体が0mmの場合、その鋸刃厚による消費長は0mmとなる。

### 3.3 部材切断と鋸刃厚

必要部材を1本切り出すごとに、部材切断用の鋸刃厚を1回分消費する。

```text
部材1本の消費長 = 部材寸法 + 鋸刃厚1回分
```

材料長を `S`、左端捨て切り寸法を `T`、鋸刃厚を `K`、切り出す部材寸法を `L1 ... Ln` とすると、材料1本の使用長と残り長さは次の式になる。

```text
使用長 = T + K + Σ(Li + K)
残り長 = S - 使用長
```

先頭の `K` は左端処理用であり、総和内の各 `K` は各部材の切断用である。同じ切断の鋸刃厚を二重計上しない。`残り長 >= 0` の配置だけを有効とする。

必要部材1本を新品母材から切り出せる条件は次のとおりである。

```text
T + K + 部材寸法 + K <= 新品母材長
```

この条件を満たさない必要部材が1種類でもある場合は、計算不能としてエラーにする。数値制約内の在庫残材から現在の必要部材を切り出せない場合は、計算全体をエラーにせず、理由付きの未使用在庫として扱う。

## 4. 材料区分

### 4.1 購入新品材

必要母材算出モードで使用する新品材と、在庫モードで在庫だけでは不足するときに追加購入する新品材である。計算結果内部では追加購入新品材を `additional_new_stock` として扱う。

### 4.2 在庫新品材

在庫として保有している未使用の新品材である。計算結果内部では `inventory_new_stock` として扱う。在庫新品材と追加購入新品材には、入力された同じ新品母材長を使用する。

### 4.3 在庫残材

過去の加工などで残った、長さを個別に入力する材料である。計算結果内部では `existing_remnant` として扱う。使用する候補内では、在庫残材を長さの短い順に処理する。

### 4.4 在庫モード内の処理

在庫残材を使用する候補では、次の順に必要部材を割り当てる。

1. 在庫残材（長さの短い順）
2. 在庫新品材
3. 不足分の追加購入新品材

ただし、この材料処理順は最終候補の優先順位ではない。在庫残材を使用しない候補も生成し、第8章の選別規則で比較するため、最終結果が常に在庫残材を使用するとは限らない。

## 5. 使い切り・廃棄材・残材の分類

切断後に材料の右端へ残った長さを、次の固定境界で分類する。

| 残り長さ | 内部値 | 表示上の分類 |
|---:|---|---|
| 0mm | `used_up` | 使い切り |
| 1～50mm | `scrap` | 廃棄材 |
| 51mm以上 | `remnant` | 発生残材 |

- 50mmと51mmの境界へ鋸刃厚を加算しない。
- 境界は鋸刃厚の値に依存しない。
- 今回の必要部材を切り出せない長さでも、残りが51mm以上なら発生残材とする。
- 使い切りは廃棄材量、発生残材量、発生残材本数のいずれにも加算しない。

## 6. パターンと寸法変更回数

### 6.1 切断パターン

- 同じ部材寸法と寸法別本数を持つ配置は、元の配置順にかかわらず同一パターンとする。
- パターンキーは `(部材寸法, 本数)` を寸法の大きい順に並べて作る。
- 同一パターンは集約し、使用回数を別に保持する。
- パターン内の表示・切断順は寸法の大きい順とする。

### 6.2 パターン実施順

異なるパターンは、寸法変更を抑える決定的な規則で並べる。最初のパターンはパターンキーの決定的な最大値とし、以降は、直前パターンの最後の寸法と次パターンの最初の寸法が一致するものを優先する。複数候補がある場合の順序もパターンキーから固定する。

これは限定されたパターン集合に対する決定的な並べ方であり、あらゆる実施順を全探索して寸法変更回数の数学的最小値を保証するものではない。

### 6.3 寸法変更回数

寸法変更回数は、決定した異なるパターンの実施順に対して次のように数える。

- パターン内：異なる部材寸法数から1を引く。
- パターン間：前パターンの最後の寸法と次パターンの最初の寸法が異なる場合に1回加算する。
- 同一パターンの使用回数は掛けない。
- 最初の寸法を設定する操作は寸法変更回数に含めない。

初回設定の有無は `initial_setup_count` として別に数え、機械設定回数は「初回設定回数 + 寸法変更回数」である。候補選別では、第8章の第7順位として寸法変更回数を使用する。

## 7. 候補生成

### 7.1 材料1本への切出し

必要部材の異なる寸法を指定された切出し順に処理する。現在の残需要全体と材料の使用可能長から概算母材本数を求め、各寸法について次の3値の最小本数をその材料へ割り当てる。

- その寸法の残必要本数
- 概算母材本数で均等化した本数
- 現在の使用可能長へ収まる本数

材料1本に割り当てた部材は、結果へ格納する際に寸法の大きい順へ正規化する。

### 7.2 必要母材算出モード

必要部材の異なる寸法について、次の2候補を生成する。

1. 寸法の大きい順で切り出す候補
2. 寸法の小さい順で切り出す候補

このモードには在庫入力がないため、必要部材が残っている間、同じ新品母材長の追加購入新品材へ割り当てる。

### 7.3 在庫母材・残材活用モード

次の4候補を生成する。

1. 寸法の大きい順・在庫残材を使用
2. 寸法の大きい順・在庫残材を使用しない
3. 寸法の小さい順・在庫残材を使用
4. 寸法の小さい順・在庫残材を使用しない

在庫残材を使用しない候補でも、入力された在庫残材は理由付き未使用在庫として結果候補へ保持する。在庫新品材は両方の候補種別で使用対象とし、それでも残る需要を追加購入新品材で完全充足する。

上記は実装上の候補生成順であり、候補の優先順位ではない。生成した全候補を同じ選別規則へ渡し、旧方式による事前削減は行わない。

## 8. 候補評価・選別

全候補を、次の順で段階的・辞書式に絞り込む。

1. 必要部材を完全充足する候補だけを残す。完全充足候補がなければ明示的な計算エラーとする。
2. 追加購入新品材数が最小の候補だけを残す。
3. 廃棄材総量が最小の候補と、最小値との差が廃棄材許容値以内の候補を残す。
4. 発生残材総量が最小の候補と、最小値との差が残材許容値以内の候補を残す。
5. 発生残材本数が最小の候補だけを残す。
6. 切断パターン数が最小の候補を優先する。
7. 寸法変更回数が最小の候補を優先する。
8. 決定的なstable keyが最小の候補を最終結果とする。

廃棄材許容値と残材許容値は独立した0以上の整数である。V1.0.1の計算エンジンはどちらも既定値0mmで呼び出すため、廃棄材総量と発生残材総量はそれぞれ最小値と完全一致する候補だけが次段階へ進む。

- 加重点評価は使用しない。
- 在庫残材の使用本数を独立した優先項目にはしない。
- 候補生成順そのものを最終判定に使用しない。
- 各候補の評価値は、固定50/51mm境界で分類した廃棄材・発生残材から集計する。

### 8.1 stable key

stable keyは次の2部分から構成する。

1. 使用材料：候補内の材料処理順を保持したまま、材料区分、元の長さ、切出し寸法順、加工後の残り長さを並べる。
2. 未使用材料：登録順に依存しないよう、材料区分、長さ、本数を並べてソートする。

未使用理由コードはstable keyに含めない。同じ物理状態へ同じ理由を付けることで、理由コードや候補生成経路が最終結果を偶発的に左右しないようにする。

## 9. 未使用在庫の理由

現行実装が出力する未使用理由コードは次の3種類だけである。

| 理由コード | 判定 |
|---|---|
| `NOT_NEEDED` | その材料を処理する時点で必要部材がすでにすべて確保されている |
| `NO_REQUIRED_PART_FITS_AFTER_TRIM` | 残需要はあるが、左端処理と部材切断の鋸刃厚を含めると、その材料から残っている必要部材を1本も切り出せない |
| `NOT_SELECTED_BY_CANDIDATE_SELECTION` | 切出可能な在庫残材だが、在庫残材を使用しない候補として生成され、候補選別の対象になった |

在庫新品材の未使用分は、必要部材がすでに確保された場合に `NOT_NEEDED` とする。在庫残材については、物理的に切出不能な状態を候補選別不採用より優先して理由付けする。

## 10. 再現性

同じ入力条件、同じアプリバージョン、同じ計算方式では、決定的な判定規則により同じ計算結果を返すことを基本とする。

- 候補生成順を最終判定基準にしない。
- 寸法順、在庫残材順、パターンキー、パターン実施順を決定的に処理する。
- 主要評価項目がすべて同値の場合だけstable keyを使用する。
- パターン番号は確定したパターン順に `P01` から付ける。
- 辞書や集合の偶発的な列挙順へ最終結果を依存させない。

管理番号と計算日時は計算時に発行される識別情報であり、計算結果の決定性には含めない。

---

## 11. 適用上の注意

- 計算結果は切断計画の支援情報であり、実作業前に材料、寸法、本数、鋸刃厚、左端捨て切り、切断順を利用者が確認する。
- 材料の変形、損傷、錆、汚れ、実測寸法、現物の使用可否は計算しない。
- 設定した新品母材長、鋸刃厚、左端捨て切り寸法を、対象材料すべてに適用できることを利用者が確認する。
- 大量の材料は、材質、規格、保管場所、作業単位などで分割して計算する。
- 完全な数学的最適解を保証しない。
