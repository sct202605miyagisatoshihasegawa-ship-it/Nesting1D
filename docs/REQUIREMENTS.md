# 1. 開発目的

定尺材および既存残材から、必要な部材を効率良く切り出すための一次元ネスティングWebアプリを開発する。

本アプリは、単純な材料歩留まりだけではなく、以下を重視する。

- 必要部材の充足
- 切断パターンの集約
- 材料セット作業の削減
- 寸法変更回数の削減
- 母材使用本数の抑制
- 残材の再利用
- 現場作業者に分かりやすい切断指示
- 同一入力に対する再現性

本アプリの中心的な価値は、材料配置だけでなく、  
**「機械をどのように動かすか」まで現場向けに表示すること**にある。

# 4. 動作モード

本アプリは2つの計算モードを持つ。

## 4.1 必要母材算出モード

同一寸法の新品母材を、必要な本数だけ用意できるものとして計算する。

### 入力

- 母材長
- 鋸刃厚
- 左端捨て切り寸法
- 必要部材寸法
- 必要本数

### 出力

- 必要母材本数
- 切断パターン
- 各パターンの使用回数
- 各母材の残材
- 廃棄材
- 切断手順

## 4.2 在庫母材・残材活用モード

現在保有している既存残材と新品母材を使用し、必要部材をどこまで用意できるか計算する。

不足分については、必要数をすべて揃えるために追加で必要な新品母材本数を表示する。

### 入力

- 新品母材長
- 保有新品母材本数
- 既存残材寸法
- 既存残材本数
- 鋸刃厚
- 左端捨て切り寸法
- 必要部材寸法
- 必要本数

### 使用優先順位

```text
使用可能な既存残材
↓
保有している新品母材
↓
追加購入する新品母材
```

### 出力

- 現在の在庫で用意できる部材数
- 寸法別の必要本数
- 寸法別の完成本数
- 寸法別の不足本数
- 追加で必要な新品母材本数
- 使用した既存残材
- 使用しなかった既存残材
- 使用した保有新品母材
- 新たに発生した残材
- 廃棄材
- 切断パターン
- 切断手順

| 項目 | 制約 |
|---|---|
| 母材長 | 1以上の整数 |
| 部材寸法 | 1以上の整数 |
| 必要本数 | 1以上の整数 |
| 鋸刃厚 | 0以上の整数 |
| 左端捨て切り寸法 | 0以上の整数 |
| 残材寸法 | 1以上の整数 |

# 7. 切断方向と基本ルール

## 7.1 切断方向

- 母材は左端から右方向へ切断する
- 右端側からの切断は考えない
- 部材の並び順と切断順は左から右とする

## 7.2 左端捨て切り

新品母材・既存残材ともに、使用開始時に左端の捨て切りを必須とする。

初期値：

```text
左端捨て切り寸法：10mm
```

左端捨て切りでは、次の長さを消費する。

```text
左端捨て切り寸法 + 鋸刃厚1回分
```

## 7.3 部材切断

左端捨て切り後は、部材1本を切り出すごとに鋸刃厚1回分を消費する。

部材1本の必要長：

```text
部材寸法 + 鋸刃厚
```

母材1本の使用長：

```text
左端捨て切り寸法
+ 左端捨て切り用の鋸刃厚
+ 部材寸法合計
+ 部材本数分の鋸刃厚
```

## 7.4 右端

- 右端の捨て切りは行わない
- 最後に残った長さを残材または廃棄材として判定する

---

# 8. 残材・廃棄材の定義

切断後に右側へ残った長さを判定する。

判定基準：

```text
50mm（鋸刃厚に依存しない固定値）
```

- 残り寸法が `0mm` の場合：使い切り
- 残り寸法が `1mm以上50mm以下` の場合：廃棄材
- 残り寸法が `51mm以上` の場合：残材

今回必要な部材寸法に利用できない長さであっても、  
判定基準を超えていれば残材として記録する。

既存残材を再使用する場合も、左端捨て切りを必須とする。

# 9. 最適化方針

## 9.1 名称

初期版の最適化方針を、次の名称とする。

**切断作業効率を重視した実用最適化**

数学的な完全最適解を必ず保証するのではなく、  
現場で扱いやすく、再現可能で、十分に良好な解を求める。

## 9.2 優先順位

生成した候補を次の段階式・辞書式順位で選別する。加重点評価は使用しない。

1. 必要部材を完全充足する
2. 追加購入新品母材数を最小化する
3. 最小廃棄材総量との差が許容値以下の候補を残す
4. 最小残材総量との差が別の許容値以下の候補を残す
5. 残材本数を最小化する
6. 切断パターン数を最小化する
7. 寸法変更回数を最小化する
8. 候補内容から生成した安定キーで最終決定する

廃棄材と残材の許容値は独立して扱い、現在の既定値はいずれも0mmとする。

---

# 10. 同一パターンの定義

使用している部材の寸法と本数が同じであれば、  
配置順にかかわらず同一切断パターンとして扱う。

例：

```text
2300、1800、950
1800、950、2300
```

上記は同一パターンとする。

表示時は、原則として寸法の大きい順に正規化する。

例：

```text
2300 × 2本
950 × 3本
```

---

# 11. 再現性

同じ入力条件、同じアプリバージョン、同じ計算方式では、  
原則として同一の計算結果を返す。

必要母材算出モードは切断順2戦略の2候補、在庫モードは切断順2戦略と既存残材の使用・不使用を組み合わせた4候補を生成する。全候補を同じ選別関数へ渡し、候補生成順は判定基準に使用しない。

最終決定用の安定キーは、使用母材種別、元長、母材順、cuts順、切断後残長、および理由コードを除いた未使用材料を不変タプルへ正規化する。主要評価項目がすべて同値の場合だけ使用する。

# 14. JSON保存

## 14.1 目的

- 再編集
- 再計算
- データ管理
- 将来のJavaScript版とのデータ交換

## 14.2 ファイル名

```text
NEST-YYYYMMDD-001.json
```

## 14.3 保存対象

- 入力条件
- 任意情報
- 計算モード
- 管理番号
- 作成日時
- 更新日時
- アプリバージョン
- データ形式バージョン
- 計算結果

## 14.4 データ形式

JSONには形式バージョンを持たせる。

例：

```json
{
  "format_version": "1.0",
  "app_version": "1.0.0",
  "management_number": "NEST-20260726-001",
  "created_at": "2026-07-26T10:00:00+09:00"
}
```

## 14.5 再読込

- 保存したJSONを再読込できる
- 入力画面へ復元できる
- 再計算できる
- 不正JSONでは異常終了しない
- 非対応バージョンの場合は利用者へ説明する

## 14.6 初期版の保存方式

- 正式なJSONとHTMLは、サーバー側のプロジェクト内 `data/` へ同時に保存する
- `data/` 外への保存を禁止し、利用者にはサーバー側絶対パスを入力させない
- 正式保存成功時だけ保存済みとし、端末へのJSON・HTMLダウンロードはコピー取得として扱う
- ダウンロード先、既存ファイル確認、原子的置換、保存完了確認はブラウザと利用端末の責務とする
- 初期版ではFile System Access APIを採用しない
- アプリ内の新規作成・JSON読込・入力リセットは保存・破棄・キャンセルを表示し、ブラウザ離脱は標準確認を使用する

# 16. 管理番号

保存時に自動採番する。

形式：

```text
NEST
+
保存日
+
連番3桁
```

例：

```text
NEST-20260726-001
```

規則：

- 新規データを初めて保存するときに発行する
- 上書き保存では同じ管理番号を維持する
- JSONとHTMLは同じ管理番号を使用する
- 連番は、その日の既存番号の最大値に1を加える
- 同名ファイルが存在する場合は上書き確認を表示する

# 18. エラー条件

以下の場合は計算を実行せず、利用者向けメッセージを表示する。

- 必須項目が空欄
- 0または負数
- 数値欄への文字入力
- 小数入力
- 必要部材が0行
- 同一行の寸法または本数が未入力
- 母材有効長が0以下
- `部材寸法 + 鋸刃厚` が使用可能長を超える
- 既存残材が捨て切り後に使用不能
- 極端に大きな数値
- 保存先へ書き込めない
- JSONが不正
- JSON形式バージョンが非対応
- 計算不能な入力組合せ
- 予期しない内部エラー

エラー時はアプリを異常終了させない。

# 19. 非機能要件

## 19.1 安全性

- 原則として外部通信を行わない
- プロジェクトフォルダ外を無断変更しない
- 利用者が指定した出力先以外へ保存しない
- 一時ファイルを利用した安全な保存を行う
- 保存途中の失敗で元データを壊さない
- 秘密情報を保存しない
- 個人パスを画面や出力へ残さない
- 任意入力をHTMLへ直接埋め込まない

## 19.2 保守性

- シンプルで読みやすいコード
- 責務分離
- 計算ロジックと画面の分離
- 計算ロジックとHTTP処理の分離
- 計算ロジックとファイル保存の分離
- 自動テスト
- 実装理由の記録
- 将来のJavaScript移植を考慮

## 19.3 性能

初期目標：

- 必要部材合計1000本程度を通常利用範囲とする
- 標準的なPCで数秒以内の計算完了を目標とする
- 計算中であることを画面に表示する
- 計算中でも利用者が処理中であると理解できる

## 19.4 再現性

- 同じ入力では同じ結果を返す
- パターン番号が不必要に入れ替わらない
- テストデータで結果を固定できる

## 19.5 対応画面

- PCブラウザ
- スマートフォン幅
- タッチ操作を考慮
- マウス操作のみに依存しない
