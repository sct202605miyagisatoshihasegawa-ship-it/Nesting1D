# 1. アプリ概要・目的

Nesting1Dは、定尺の新品母材、在庫新品材、および在庫残材から必要な部材を切り出すための一次元ネスティングWebアプリケーションである。

本アプリは、次の情報を一つの切断計画として提示する。

- 必要部材の充足状況
- 必要な購入新品材本数
- 切断パターンと使用回数
- 実際に使用する材料と切出し部材
- 加工後の発生残材、廃棄材、使い切り
- 現場で実行する切断手順
- 寸法変更回数と機械設定回数

本アプリの目的は、材料配置の計算だけでなく、同一パターンの集約と現場向け切断手順により、材料セット作業、寸法変更、および切断ミスの抑制を支援することである。

# 2. 対象範囲

## 2.1 対象とする加工

- 長さだけで表す一次元材料を対象とする。
- 入力単位はミリメートル（mm）とする。
- すべての寸法、本数、鋸刃厚、および左端捨て切り寸法は整数とする。
- 同時に使用できる同一の材質、規格、加工条件の材料を1回の計算単位とする。

## 2.2 V1.0.1に含まれる機能

- 必要母材算出モード
- 在庫母材・残材活用モード
- 在庫残材、在庫新品材、および追加購入新品材の計算
- 複数の貪欲的戦略による候補生成と段階的候補選別
- パターン集約、使用材料一覧、未使用在庫と理由、切断手順の表示
- JSONとHTMLの端末への直接出力
- ブラウザのFile APIによる端末JSON読込
- PCブラウザとスマートフォン幅のレスポンシブ表示

## 2.3 V1.0.1の機能境界

V1.0.1は、次の機能を持たない。

- ログイン、認証、ユーザー管理
- データベースやサーバー上の利用者データ保存
- 保存済み一覧、履歴、検索、上書き保存、再ダウンロード
- 二次元または三次元ネスティング
- 複数の新品母材長、複数材質、複数設備の同時計算
- 原価計算
- JSONとHTML以外の直接入出力
- ページ再読込後の計算結果・出力状態の復元

- Python 3.11
- FastAPI
- Pydantic

- HTML

## 3.2 処理構成

```text
Webブラウザ
    ↓ HTMLフォーム / JSON・HTML出力リクエスト
FastAPI
    ↓ 検証済み計算入力
Python計算エンジン
    ↓ 決定的な計算結果
```

計算エンジンは、FastAPIのHTTP処理、Jinja2の表示処理、および出力レコード生成から分離する。サーバーはリクエスト処理中のメモリ上で計算と出力生成を行う。

- HTTPS終端はCloud Runが提供する。
- アプリケーション自身は利用者データを永続保存しない。

# 4. 計算モード

## 4.1 必要母材算出モード

同一長さの購入新品材を必要な本数だけ用意できるものとして、入力された必要部材をすべて切り出す計画を計算する。

入力：

- 新品母材長
- 鋸刃厚
- 左端捨て切り寸法
- 必要部材の寸法と必要本数

主な結果：

- 使用する購入新品材本数
- 切断パターンと使用回数
- 使用材料ごとの切出し部材と加工後の状態
- 発生残材、廃棄材、使い切り
- 切断手順

## 4.2 在庫母材・残材活用モード

以下の3種類の材料を扱い、必要部材をすべて切り出す計画を計算する。

- 在庫残材
- 在庫新品材
- 追加購入する新品材

在庫新品材と追加購入新品材は、同じ新品母材長を使用する。

在庫残材の使用を常に強制するものではない。在庫残材を使用する候補と使用しない候補の両方を生成し、追加購入新品材数、廃棄材量、残材量、作業性などの選別順位により最終候補を決定する。

各候補内で在庫残材を使用する場合は、寸法の短い在庫残材から処理し、次に在庫新品材、最後に不足分の追加購入新品材を使用する。

主な結果：

- 在庫残材の使用本数
- 在庫新品材の使用本数
- 追加購入新品材本数
- 在庫で完成した寸法別本数
- 追加購入前の不足本数と購入後の充足状況
- 使用材料、未使用在庫と理由
- 切断パターン、加工後状態、切断手順

# 5. 入力項目

## 5.1 共通情報

次の項目は任意入力とする。

| 項目 | 内容 |
|---|---|
| 件名 | 計算対象を識別する名称 |
| 材料種類 | 材料の種類や呼称 |
| データ製作者 | 入力データの作成者 |
| 備考 | 案件や加工に関する任意メモ |

## 5.2 切断条件

| 項目 | 内容 |
|---|---|
| 新品母材長 | 購入新品材と在庫新品材に共通する長さ |
| 鋸刃厚 | 1回の切断で消費する鋸刃幅 |
| 左端捨て切り寸法 | 使用開始時に材料左端から捨てる長さ |

左端捨て切り寸法の初期値は10mmである。廃棄判定基準は50mm固定であり、利用者入力項目ではない。

## 5.3 必要部材

必要部材は複数行で入力する。1行は次の値を持つ。

- 寸法（mm）
- 必要本数

同一寸法が複数行に入力された場合は、計算時に必要本数を合算する。

## 5.4 在庫情報

在庫母材・残材活用モードだけで使用する。

- 在庫新品材本数
- 在庫残材の寸法（mm）と保有本数

在庫残材は0行以上の複数行を入力できる。

# 6. 入力制約

## 6.1 数値・行数制約

| 項目 | V1.0.1の制約 |
|---|---:|
| 必要部材行数 | 1～20行 |
| 在庫残材行数 | 0～10行 |
| 必要部材1行の本数 | 1～500本 |
| 在庫残材1行の本数 | 1～500本 |
| 在庫新品材本数 | 0～500本 |
| 新品母材長 | 1～6100mm |
| 必要部材寸法 | 1～6100mm |
| 在庫残材寸法 | 1～6100mm |
| 鋸刃厚 | 0～100mm |
| 左端捨て切り寸法 | 0～100mm |

- 小数、負数、数値欄への文字列は受け付けない。
- 必要部材は最低1行の有効入力を必須とする。
- 寸法と本数の片方だけが入力された行はエラーとする。
- 必要部材合計本数に独立した100万本上限は設けない。
- 入力構造上の必要部材合計の最大値は、20行 × 500本 = 10,000本である。

## 6.2 任意文字入力の制約

| 項目 | 最大文字数 |
|---|---:|
| 件名 | 20文字 |
| 材料種類 | 30文字 |
| データ製作者 | 30文字 |
| 備考 | 400文字 |

文字数はPythonの文字列長で判定する。HTMLフォームにも同じ最大文字数を設定する。

## 6.3 切出可否に関する制約

必要部材1本に必要な長さが次の式で新品母材長を超える場合は、計算を行わない。

```text
左端捨て切り寸法
+ 左端捨て切り用の鋸刃厚1回分
+ 必要部材寸法
+ 部材切断用の鋸刃厚1回分
> 新品母材長
```

数値制約内の在庫残材が、左端捨て切り後に現在の必要部材を1本も切り出せない場合は、全体を入力エラーとしない。その材料を未使用在庫とし、理由を結果に表示する。

# 7. 切断条件・加工ルール

## 7.1 切断方向

- 材料は左端から右方向へ切断する。
- 右端側からの切断は行わない。
- 右端捨て切りは行わない。

## 7.2 左端捨て切り

- 購入新品材、在庫新品材、在庫残材のいずれも、使用開始時に左端捨て切りを行う。
- 在庫残材を再使用する場合も同じ規則を適用する。
- 左端捨て切りでは次の長さを消費する。

```text
左端捨て切り寸法 + 鋸刃厚1回分
```

## 7.3 部材切断

- 左端捨て切り後、部材1本を切り出すごとに鋸刃厚1回分を消費する。
- 部材1本の切出しに必要な長さは、「部材寸法 + 鋸刃厚」である。
- 材料1本の使用長は次の式で計算する。

```text
左端捨て切り寸法
+ 左端捨て切り用の鋸刃厚1回分
+ 切り出した部材寸法の合計
+ 切り出した部材本数分の鋸刃厚
```

## 7.4 パターンと寸法変更

- 切り出す部材の寸法と本数が同じであれば、配置順にかかわらず同一切断パターンとする。
- 同一パターンの部材は寸法の大きい順に正規化して表示する。
- 同一パターンはまとめて加工する。
- 同一パターン内の寸法変更回数は、異なる寸法数から1を引いた値とし、パターンの使用回数は掛けない。
- 初回の寸法設定は寸法変更回数に含めない。
- パターン間で前パターンの最後と次パターンの最初の寸法が異なる場合は、寸法変更を1回加算する。
- パターンの実施順は寸法変更回数が少なくなるよう決定し、同点時の順序を固定する。

# 8. 残材・廃棄材の定義

材料の右端に残った長さを次の固定境界で分類する。

| 残り長さ | 分類 |
|---:|---|
| 0mm | 使い切り |
| 1～50mm | 廃棄材 |
| 51mm以上 | 発生残材 |

- 境界値50mmに鋸刃厚を加えない。
- この分類境界は鋸刃厚に依存しない。
- 今回必要な部材を切り出せない長さであっても、51mm以上であれば発生残材として記録する。
- 使い切りは発生残材と廃棄材のどちらにも含めない。

# 9. 計算・候補選別方針

## 9.1 基本方針

「切断作業効率を重視した実用最適化」として、限定された複数候補を貪欲的に生成し、材料効率と作業性を段階的に比較する。

完全な数学的最適解や、すべての配置組合せの全探索は保証しない。

## 9.2 候補生成

必要部材の異なる寸法を次の2通りに並べ、各順序でバランスを取りながら切り出し本数を決定する。

1. 寸法の大きい順
2. 寸法の小さい順

生成する候補数は次のとおりである。

| 計算モード | 候補戦略 | 候補数 |
|---|---|---:|
| 必要母材算出 | 切断寸法順2通り | 2 |
| 在庫母材・残材活用 | 切断寸法順2通り × 在庫残材の使用・不使用 | 4 |

必要部材の生成本数は同一候補内で共有し、各材料を処理するごとに残数を減らす。在庫モードで在庫残材を使用する候補は、在庫残材、在庫新品材、追加購入新品材の順に割り当てる。

## 9.3 候補選別順位

生成したすべての候補を次の段階式・辞書式順位で選別する。加重点評価は使用しない。

1. 必要部材を完全充足する候補に限定する。
2. 追加購入新品材数を最小化する。
3. 廃棄材総量を最小化する。
4. 発生残材総量を最小化する。
5. 発生残材本数を最小化する。
6. 切断パターン数を最小化する。
7. 寸法変更回数を最小化する。
8. 決定的な安定キーで最終決定する。

廃棄材と発生残材の許容値は独立しており、V1.0.1の既定値はどちらも0mmである。したがって、V1.0.1では各段階の最小値と完全一致する候補だけが次の比較へ進む。

## 9.4 安定キー

最終タイブレークでは、次の内容を不変値へ正規化した安定キーを使用する。

- 使用材料の種別
- 元の材料長
- 材料の処理順
- 切り出し寸法の順列
- 加工後の残り長さ
- 未使用材料の種別、長さ、本数

未使用理由コードは安定キーに含めない。同じ物理状態には候補経路にかかわらず同じ理由を付与する。

## 9.5 未使用在庫の理由

在庫モードは、未使用の在庫残材または在庫新品材に対して理由を保持する。

- 必要部材がすでにすべて確保されている。
- 左端捨て切り後の長さで、残っている必要部材を1本も切り出せない。
- 候補選別の結果、その材料を使用しない計画が選ばれた。

# 10. 再現性

同じ入力条件、同じアプリバージョン、同じ計算方式では、決定的な判定規則により同じ計算結果を返すことを基本とする。

- 候補生成順そのものを最終判定基準に使用しない。
- 主要評価項目がすべて同値の場合だけ安定キーを使用する。
- パターン番号、パターン実施順、使用材料順、未使用理由を決定的に処理する。

管理番号と計算日時は計算時に発行される識別情報であり、計算結果の決定性とは分けて扱う。

# 12. JSON / HTML出力

## 12.1 データ取り扱い

- JSONとHTMLは、出力リクエストの処理中にサーバーメモリ上で生成し、利用者端末へ直接ダウンロードする。
- サーバー上へ入力内容、計算結果、JSON、HTML、一時ファイル、または計算履歴を永続保存しない。
- サーバー保存済み一覧と上書き保存は提供しない。
- JSONとHTMLの出力レスポンスには`Cache-Control: no-store`を設定する。
- 入力内容、管理情報、備考、計算結果、JSON全文、HTML全文をアプリケーションログへ記録しない。
- ページ内の管理番号、日時、計算結果、出力状態をデータベース、Cookie、またはブラウザ永続ストレージへ保存しない。

## 12.2 JSON出力形式

JSONファイル名は次の形式とする。

```text
NEST-YYYYMMDD-HHMMSS-XXXX.json
```

JSONは次の主要項目を含む。

- JSON形式バージョン
- アプリバージョン
- 管理番号
- 作成日時と更新日時
- 計算モード
- 共通情報
- 切断条件
- 必要部材
- 在庫情報
- 計算結果

バージョンの例：

```json
{
  "format_version": "1.0",
  "app_version": "1.0.1"
}
```

`app_version`はNesting1D本体のバージョン、`format_version`はJSONデータ構造の互換性を示すバージョンである。

## 12.3 端末JSON読込

- ブラウザのFile APIで端末ファイルを読み取る。
- JSONファイル本体をサーバーへ送信しない。
- 読込後はJSONの入力情報をフォームへ復元し、保存済みの計算結果は表示に使用しない。利用者は再計算を実行する。
- 読込失敗時は現在の入力状態を維持し、利用者向けエラーを表示する。

ローカルJSON読込時に次を検証する。

| 項目 | 制約 |
|---|---|
| ファイル拡張子 | `.json` |
| MIME type | 空値、`application/json`、`text/json`、または`+json`で終わる値 |
| ファイルサイズ | 5MiB以下 |
| JSON深さ | 8以下 |
| JSON形式バージョン | `1.0` |
| 必要部材 | 1～20行、寸法1～6100mm、本数1～500本 |
| 在庫残材 | 0～10行、寸法1～6100mm、本数1～500本 |
| 在庫新品材 | 0～500本 |
| 切断条件 | 新品母材長1～6100mm、鋸刃厚0～100mm、左端捨て切り0～100mm |
| 管理番号・日時 | 対応形式と`Asia/Tokyo`オフセット |

共通情報は文字列であることを読込時に確認する。第6.2節の個別文字数制約は、読込後の再計算用フォームPOSTでも検証する。

## 12.4 HTML出力

HTMLファイル名は次の形式とする。

```text
NEST-YYYYMMDD-HHMMSS-XXXX.html
```

HTMLは次を満たす。

- UTF-8
- 利用者入力のHTMLエスケープ
- CSSをHTML内に内包
- 外部CDNや外部リソースに依存しない自己完結形式
- ブラウザでの閲覧と印刷
- 印刷CSSのA4ページ設定
- `noindex, nofollow, noarchive`

主な出力内容：

- 件名、日付、管理番号、材料種類、データ製作者、備考
- 計算モードと切断条件
- 必要部材と在庫情報
- 結果概要と寸法別充足状況
- パターン一覧と使用材料一覧
- 切断手順
- 発生残材、廃棄材、使い切り
- 未使用在庫と理由
- アプリバージョンとJSON形式バージョン

HTML生成は入力レコードと計算結果を変更しない。

---

# 13. 管理番号と識別情報

管理番号はサーバー保存番号ではなく、計算結果を識別するためのIDである。

## 13.1 現行形式

```text
NEST-YYYYMMDD-HHMMSS-XXXX
```

- 日時は明示的に`Asia/Tokyo`を使用する。
- `XXXX`は`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`から、暗号学的に安全な乱数選択で4文字を生成する。
- 計算成功時に発行する。
- 入力が変更されていない間は、管理番号、作成日時、更新日時を維持する。
- 入力変更後の再計算では、管理番号と両日時を新しく発行する。
- JSONとHTMLは同じ管理番号、作成日時、更新日時を使用する。

## 13.2 対応する旧形式

端末JSON読込では次の旧管理番号も受け付ける。

```text
NEST-YYYYMMDD-NNN
```

旧形式の端末JSONを読み込み、入力未変更のまま再計算した場合は、読み込んだ管理番号と日時を維持する。

# 14. エラー処理

## 14.1 入力エラー

次の場合は計算を実行せず、入力画面に利用者向けのエラーを表示する。

- 必須項目が空欄
- 数値が許容範囲外
- 数値欄に文字、小数、または負数が入力された
- 必要部材が0行
- 同一行の寸法または本数の一方が未入力
- 必要部材または在庫残材の行数が上限を超えた
- 共通情報が文字数上限を超えた
- 左端捨て切りと鋸刃厚を含めると、必要部材を新品母材から1本も切り出せない
- 計算モードと在庫入力構造が一致しない

エラー時は入力値を保持し、対象入力欄にインラインエラーを表示する。

## 14.2 JSON読込・出力エラー

次の場合は現在状態を可能な範囲で維持し、利用者向けメッセージを表示する。

- JSONが不正、必要項目不足、または対応外形式バージョン
- JSONファイルの種類、サイズ、深さ、行数、または数値が制約外
- 管理番号または日時の形式が不正
- JSONまたはHTMLの出力リクエストが不正
- JSONまたはHTMLの生成・ダウンロード開始に失敗

予期しない内部例外の詳細、スタックトレース、入力全文はレスポンスに含めない。

## 14.3 HTTP本文エラー

- HTTPリクエスト本文が設定上限を超えた場合はHTTP 413と`{"detail":"Request body too large"}`を返す。
- `Content-Length`が負数相当、数字以外、複数ヘッダー、またはカンマ区切りの場合はHTTP 400と`{"detail":"Invalid Content-Length"}`を返す。
- `Content-Length`が上限以下または存在しない場合でも、ASGIで実際に受信したバイト数を検査する。

# 15. 非機能要件

## 15.1 データ保護

- サーバーへ利用者の入力内容と計算結果を永続保存しない。
- 端末JSON読込はブラウザ内で完結し、ファイル本体をサーバーへアップロードしない。
- アプリケーションログへ利用者データ全文を出力しない。
- HTML出力時は利用者入力をHTMLエスケープする。

## 15.2 公開環境のセキュリティ

- Cloud RunがHTTPSを提供する。
- `APP_ENV`が大文字・小文字を問わず`production`の場合、`/docs`、`/redoc`、`/openapi.json`を公開しない。
- 全HTTPレスポンスに次のヘッダーを設定する。
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Referrer-Policy: no-referrer`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- HTMLレスポンス、JSON・HTML出力、`robots.txt`、400・413の受信エラーに適切な`Cache-Control: no-store`を設定する。
- 画面と出力HTMLに`noindex, nofollow, noarchive`を設定する。
- `/robots.txt`はすべてのクロールを拒否するよう依頼する。`robots.txt`はアクセス制御としては扱わない。

## 15.3 HTTPリクエスト本文サイズ

- 既定上限は64KiB（65536バイト）とする。
- 環境変数`MAX_REQUEST_BODY_BYTES`の1以上のASCII十進整数で変更できる。
- 未設定または空文字の場合は既定値を使用する。不正な設定値は起動時エラーとする。

## 15.4 表示と対応端末

- PCブラウザで操作できる。
- スマートフォン幅で主要領域を1カラム化する。
- タッチとキーボードで操作でき、マウス操作だけに依存しない。

## 15.5 性能と処理範囲

- 第6章のV1.0.1入力上限内で利用する設計とする。
- 入力上限は実務上推奨する1回の計算単位を意味しない。材料数が多い場合は、材質、規格、保管場所、または作業単位で分割して計算する。
- 計算フォーム送信中は計算ボタンを無効化し、処理中表示を行う。

## 15.6 再現性と保守性

- 同一条件に対する計算は第10章の再現性規則に従う。
- 計算ロジックをHTTP処理、画面表示、および出力生成から分離する。
- 自動テストで基本計算、境界値、異常入力、再現性、Web表示、JSON・HTML出力、公開設定を確認する。

---

# 16. 適用範囲と利用上の注意

- 本アプリは一次元材料の切断計画を対象とする。
- 完全な数学的最適解を保証しない。
- 現場で実行しやすい切断計画の作成を支援するツールである。
- 大量の材料は、材質、規格、保管場所、または作業単位などで分割して計算する。
- 同時に使用できる材料だけを同じ計算に入力する。
- 入力した新品母材長、鋸刃厚、左端捨て切り寸法を加工条件として計算する。
- 材料の変形、損傷、錆、汚れ、実測寸法、および現物の使用可否は計算しない。利用者が判断する。
- 計算結果は支援情報であり、実作業前に材料、寸法、本数、鋸刃厚、捨て切り、切断手順を利用者が確認する。
- サーバーは入力内容と計算結果を永続保存しない。必要なデータは利用者がJSONまたはHTMLを端末へ出力して管理する。
- ブラウザの再読込やページ離脱により、未出力の入力・計算結果を失う可能性がある。
