# Nesting1D V1.0.1 計算例

- 対象アプリバージョン：1.0.1
- 更新日：2026-08-10

## 1. 文書の目的

この文書は、Nesting1D V1.0.1の計算・切断ルールを具体的な入力と現行計算エンジンの出力で説明する理解補助資料である。

- 現行機能と入力制約： [REQUIREMENTS.md](REQUIREMENTS.md)
- 計算・切断ルール： [CALCULATION_RULES.md](CALCULATION_RULES.md)
- 入出力データ契約： [INPUT_OUTPUT_SCHEMA.md](INPUT_OUTPUT_SCHEMA.md)
- 設計判断： [DECISIONS.md](DECISIONS.md)

以下の寸法はすべてmmである。各例の入力はV1.0.1の入力範囲内であり、記載した結果は現行の`app/calculation/`で実計算して確認している。完全な数学的最適解を示すものではなく、現行エンジンが生成した候補を現行の選別規則で決定した結果である。

---

## 2. 例1：基本的な必要母材算出

### 目的

左端処理と部材切断で消費する鋸刃厚、および廃棄材の発生を確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 必要母材算出 |
| 新品母材長 | 1,030 |
| 鋸刃厚 | 5 |
| 左端捨て切り | 10 |
| 必要部材 | 500 × 2本 |

### 計算上のポイント

```text
左端処理 = 10 + 5 = 15
部材2本 = (500 + 5) × 2 = 1,010
使用長 = 15 + 1,010 = 1,025
残り = 1,030 - 1,025 = 5
```

### 計算結果

- 購入新品材：1本
- 切出し順：`[500, 500]`
- 使用長：1,025
- 残り：5、`scrap`（廃棄材）
- パターン：`P01 = 500 × 2本`を1回
- 寸法変更回数：0、初回設定回数：1、機械設定回数：1

### この例から分かること

左端処理用の鋸刃厚1回分と、部材2本を切り出す鋸刃厚2回分を別々に消費する。残り5mmは固定境界1～50mmに該当するため廃棄材である。

## 3. 例2：配置可否と左端捨て切り0mm

### 目的

左端捨て切りが0mmでも左端処理用の鋸刃厚を消費することと、配置可否の境界を確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 必要母材算出 |
| 新品母材長 | 110 |
| 鋸刃厚 | 5 |
| 左端捨て切り | 0 |
| 必要部材 | 100 × 1本 |

### 計算上のポイント

```text
使用長 = 0 + 5 + (100 + 5) = 110
```

左端捨て切り寸法自体は0mmだが、左端処理用の鋸刃厚5mmは消費する。続いて部材切断用の鋸刃厚5mmを1回消費する。

### 計算結果

- 購入新品材：1本
- 切出し順：`[100]`
- 使用長：110
- 残り：0、`used_up`（使い切り）

同じ鋸刃厚・左端捨て切り・部材寸法で新品母材長を109mmにすると、必要長110mmに1mm不足するため計算不能となる。

### この例から分かること

左端捨て切り0mmは左端処理全体の省略を意味しない。現行実装では、鋸刃厚が0mmでない限り左端処理用の鋸刃厚1回分を必ず計上する。

## 4. 例3：左端捨て切り寸法の変更

### 目的

入力した左端捨て切り寸法が使用長と発生残材へ反映されることを確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 必要母材算出 |
| 新品母材長 | 1,000 |
| 鋸刃厚 | 3 |
| 左端捨て切り | 20 |
| 必要部材 | 400 × 2本 |

### 計算上のポイント

```text
使用長 = 20 + 3 + (400 + 3) × 2 = 829
残り = 1,000 - 829 = 171
```

### 計算結果

- 購入新品材：1本
- 切出し順：`[400, 400]`
- 使用長：829
- 残り：171、`remnant`（発生残材）

### この例から分かること

購入新品材、在庫新品材、在庫残材のいずれも、使用開始時は同じ「左端捨て切り寸法 + 鋸刃厚1回分」の規則を使用する。

## 5. 例4：残り50mmと51mmの固定境界

### 目的

廃棄材と発生残材の50/51mm境界が、鋸刃厚を加算しない固定値であることを確認する。

### 共通入力

| 項目 | 値 |
|---|---:|
| 計算モード | 必要母材算出 |
| 鋸刃厚 | 5 |
| 左端捨て切り | 10 |
| 必要部材 | 100 × 1本 |

左端処理と部材1本の使用長は、どちらのケースも次のとおりである。

```text
使用長 = 10 + 5 + (100 + 5) = 120
```

### 計算結果

| 新品母材長 | 使用長 | 残り | 内部分類 | 表示分類 |
|---:|---:|---:|---|---|
| 170 | 120 | 50 | `scrap` | 廃棄材 |
| 171 | 120 | 51 | `remnant` | 発生残材 |

### この例から分かること

鋸刃厚5mmは使用長にすでに反映されている。分類時に50mmへ鋸刃厚を再度加えず、残り長さそのものを固定境界で判定する。残り0mmは別区分の`used_up`である。

---

## 6. 例5：同一寸法の合算とパターン集約

### 目的

複数行に分かれた同一寸法の合算、同一パターンの集約、および寸法変更回数を確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 必要母材算出 |
| 新品母材長 | 1,000 |
| 鋸刃厚 | 0 |
| 左端捨て切り | 0 |
| 必要部材1 | 400 × 1本 |
| 必要部材2 | 300 × 2本 |
| 必要部材3 | 400 × 1本 |

### 計算上のポイント

400mmは合計2本、300mmは合計2本として扱う。現行エンジンは各新品材へ`[400, 300]`を配置する。

```text
材料1本の使用長 = 0 + 0 + 400 + 300 = 700
材料1本の残り = 1,000 - 700 = 300
```

### 計算結果

- 購入新品材：2本
- 切出し順：両方とも`[400, 300]`
- パターン：`P01 = 400 × 1本 + 300 × 1本`を2回
- 各材料の残り：300、`remnant`
- 発生残材：300mm × 2本、合計600mm
- 寸法変更回数：1、初回設定回数：1、機械設定回数：2

### この例から分かること

同じ寸法は入力行をまたいで合算される。同じ寸法別本数の切断は1パターンへ集約され、パターン使用回数2として表される。寸法変更回数にはパターン使用回数を掛けない。

## 7. 例6：在庫残材を使わない候補が選ばれる場合

### 目的

在庫残材が切出可能でも必ず使用するわけではなく、4候補の段階的選別で最終計画を決めることを確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 在庫母材・残材活用 |
| 新品母材長 | 1,000 |
| 鋸刃厚 | 0 |
| 左端捨て切り | 0 |
| 必要部材 | 600 × 1本、400 × 1本 |
| 在庫新品材 | 1本 |
| 在庫残材 | 600 × 1本 |

### 候補比較

現行エンジンが生成する4候補の評価値は次のとおりである。表の残材量は切断後に新たに発生する残り長さの合計であり、未使用在庫残材の長さは含まない。

| 候補 | 追加購入 | 廃棄材量 | 発生残材量 | 発生残材本数 | パターン数 | 寸法変更 |
|---|---:|---:|---:|---:|---:|---:|
| 寸法降順・在庫残材を使用 | 0 | 0 | 600 | 1 | 2 | 1 |
| 寸法降順・在庫残材を不使用 | 0 | 0 | 0 | 0 | 1 | 1 |
| 寸法昇順・在庫残材を使用 | 0 | 0 | 600 | 2 | 2 | 1 |
| 寸法昇順・在庫残材を不使用 | 0 | 0 | 0 | 0 | 1 | 1 |

4候補はすべて完全充足し、追加購入0本、廃棄材0mmで同じである。次の比較項目である発生残材量が0mmの不使用候補だけが残る。候補生成順を優先条件には使わない。

### 計算結果

- 使用した在庫残材：0本
- 使用した在庫新品材：1本
- 追加購入新品材：0本
- 在庫新品材の切出し順：`[600, 400]`
- 在庫新品材の残り：0、`used_up`
- 在庫残材600mm：未使用
- 未使用理由：`NOT_SELECTED_BY_CANDIDATE_SELECTION`

### この例から分かること

材料処理順と候補選別順位は別である。「残材がある」「追加購入数が同じ」という条件だけでは残材使用を優先しない。現行の辞書式順位では、この例は発生残材量の少ない計画を選ぶ。

## 8. 例7：在庫新品材を使った後に追加購入する場合

### 目的

在庫新品材だけでは不足するとき、同じ新品母材長の追加購入新品材で完全充足することを確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 在庫母材・残材活用 |
| 新品母材長 | 1,000 |
| 鋸刃厚 | 0 |
| 左端捨て切り | 0 |
| 必要部材 | 600 × 2本、400 × 1本 |
| 在庫新品材 | 1本 |
| 在庫残材 | なし |

### 計算結果

| 材料区分 | 元の長さ | 切出し順 | 使用長 | 残り | 分類 |
|---|---:|---|---:|---:|---|
| 在庫新品材 | 1,000 | `[600, 400]` | 1,000 | 0 | `used_up` |
| 追加購入新品材 | 1,000 | `[600]` | 600 | 400 | `remnant` |

- 使用材料：2本
- 使用した在庫新品材：1本
- 追加購入新品材：1本
- 発生残材：400mm × 1本
- パターン：2種類
- 寸法変更回数：2、初回設定回数：1、機械設定回数：3

### この例から分かること

在庫新品材と追加購入新品材は同じ入力母材長を使う。現行エンジンは在庫新品材へ割り当てた後、残需要を追加購入新品材で完全充足する。

## 9. 例8：使用不能な在庫残材

### 目的

数値範囲内だが必要部材を1本も切り出せない在庫残材を、入力エラーではなく理由付き未使用在庫として扱うことを確認する。

### 入力条件

| 項目 | 値 |
|---|---:|
| 計算モード | 在庫母材・残材活用 |
| 新品母材長 | 1,000 |
| 鋸刃厚 | 5 |
| 左端捨て切り | 10 |
| 必要部材 | 100 × 1本 |
| 在庫新品材 | 0本 |
| 在庫残材 | 100 × 1本 |

### 計算上のポイント

在庫残材から必要部材1本を切り出すには次の120mmが必要である。

```text
10 + 5 + (100 + 5) = 120
```

在庫残材は100mmしかないため20mm不足する。

### 計算結果

- 使用した在庫残材：0本
- 在庫残材100mm：`NO_REQUIRED_PART_FITS_AFTER_TRIM`で未使用
- 追加購入新品材：1本
- 購入新品材の切出し順：`[100]`
- 購入新品材の使用長：120
- 購入新品材の残り：880、`remnant`

### この例から分かること

入力範囲内の在庫残材が使用不能でも計算全体は中止しない。切出可能な新品材で必要部材を充足し、在庫残材を使用しなかった物理的理由を結果へ保持する。

## 10. 例9：入力行順と再現性

### 目的

必要部材の入力行順を変えても、正規化後の要求と最終結果が変わらないことを確認する。

### 入力Aと入力B

切断条件は例5と同じとし、必要部材行だけを次のように入れ替える。

```text
入力A: 400 × 2本、300 × 2本
入力B: 300 × 2本、400 × 2本
```

### 計算結果

現行エンジンによる両方の`CalculationResult`は一致する。

- 購入新品材：2本
- 各材料の切出し順：`[400, 300]`
- パターン：`P01 = 400 × 1本 + 300 × 1本`を2回
- 各材料の残り：300、`remnant`
- 寸法変更回数：1

### この例から分かること

入力された行の列挙順そのものを最終判定基準には使用しない。同じ入力条件、同じアプリバージョン、同じ計算方式では、決定的な寸法順、パターン順、候補選別、stable keyにより同じ結果を返すことを基本とする。

## 11. 入力範囲に関する注意

本書の例は、計算結果を理解しやすい小さな入力に限定している。V1.0.1では必要部材最大20行、在庫残材最大10行、各行最大500本であり、独立した合計必要本数制限はない。必要部材の入力構造上の最大は20 × 500 = 10,000本である。

寸法、本数、加工条件を含む完全な入力範囲とエラー条件は [REQUIREMENTS.md](REQUIREMENTS.md) を、JSONフィールドと型は [INPUT_OUTPUT_SCHEMA.md](INPUT_OUTPUT_SCHEMA.md) を参照する。
